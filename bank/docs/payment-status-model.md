# Статусная модель платежа

Каждая операция перевода проходит через статусы. Банк хранит историю статусов операции с банковским временем каждого перехода и причиной для отказов. История видна клиенту в карточке операции и оператору в офисе.

## Статусы

| Статус | Что значит | Конечный | Учитывается в суточном лимите |
| --- | --- | --- | --- |
| `CREATED` | Перевод создан | нет | да |
| `CHECKING` | Идут проверки: арест, лимит, антифрод | нет | да |
| `ON_REVIEW` | Ждёт решения оператора | нет | нет |
| `PROCESSING` | Проводится: внутри банка или ждёт ответа СБП | нет | да |
| `COMPLETED` | Выполнен | да | да |
| `REJECTED` | Отклонён до проведения: лимит, арест, ограничения, антифрод, оператор, просрочка проверки | да | нет |
| `FAILED` | Не выполнен: отказ банка получателя или недоступность СБП | да | нет |
| `REFUNDED` | Возвращён: СБП не ответила вовремя, деньги вернулись клиенту | да | нет |

## Переходы

| Из | В | Когда |
| --- | --- | --- |
| `CREATED` | `CHECKING` | Сразу после создания |
| `CHECKING` | `PROCESSING` | Проверки пройдены, оценка антифрода меньше 70 |
| `CHECKING` | `ON_REVIEW` | Оценка антифрода от 70 до 89 |
| `CHECKING` | `REJECTED` | Лимит, арест, нерезидент в другой банк, оценка 90 и больше |
| `ON_REVIEW` | `PROCESSING` | Оператор одобрил |
| `ON_REVIEW` | `REJECTED` | Оператор отклонил (`OPERATOR_REJECTED`) или срок проверки истёк (`REVIEW_EXPIRED`) |
| `PROCESSING` | `COMPLETED` | Внутренний перевод проведён или СБП приняла перевод |
| `PROCESSING` | `FAILED` | Банк получателя отказал (`SBP_REJECTED`) или СБП недоступна (`SBP_UNAVAILABLE`) |
| `PROCESSING` | `REFUNDED` | СБП не ответила вовремя (`SBP_TIMEOUT`) |

Других переходов нет. Из конечного статуса операция никуда не переходит.

Перевод между своими счетами проходит `CREATED → CHECKING → PROCESSING → COMPLETED` сразу, без антифрода.

## Деньги на каждом шаге

| Шаг | Что происходит со счётом |
| --- | --- |
| `CHECKING`, после проверки ареста, ограничений, лимита и средств | Сумма перевода и комиссии замораживается (холд) и остаётся замороженной, пока перевод проверяется антифродом, ждёт оператора и проводится |
| `COMPLETED` | Проводки: списание суммы и комиссии, холд снят |
| `REJECTED` после холда, `FAILED` | Холд снят, проводок нет |
| `REFUNDED` | Две проводки: списание и возврат той же суммы, холд снят |

## События

Каждый переход публикуется в Kafka в топик `bank.payments.status-changed` с ключом — номером клиента. Создание перевода — событие в `bank.payments.created`. Формат событий — в документе «События (AsyncAPI)».
