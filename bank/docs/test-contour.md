## Вход через API

Код входа не приходит в ответе банка: банк «отправляет его СМС», а СМС учебного телефона показывает отдельный запрос. В Swagger (http://localhost:18400/api/docs) для клиента с телефоном `+79001110001`:

1. `POST /api/v1/auth/login`, тело `{"phone": "+79001110001"}` — в ответе `challengeId`.
2. `GET /api/v1/sandbox/sms`, параметр `phone` = `+79001110001` — первое сообщение в списке: «ЗапускБанк: код входа 123456…». Возьмите шесть цифр.
3. `POST /api/v1/auth/verify`, тело `{"challengeId": "…", "code": "123456"}` — в ответе `accessToken`.
4. Кнопка «Authorize» вверху Swagger — вставьте `accessToken`. Теперь запросы идут от имени этого клиента.

Проверка: `GET /api/v1/accounts` отвечает 200 и показывает счета клиента. Код действует 5 минут; новый `login` отменяет старый код. Чтобы войти другим клиентом, повторите шаги с его телефоном и замените токен в «Authorize». В Postman и curl то же самое: токен передаётся заголовком `Authorization: Bearer <accessToken>`.

## Операторы

Вход в операционный офис — по логину и паролю. Токен оператора передаётся в заголовке `Authorization: Bearer` так же, как токен клиента.

| Логин | Пароль | Роль |
| --- | --- | --- |
| operator | operator-2026 | Оператор: разбирает ручную проверку, смотрит клиентов, операции, тарифы и журнал уведомлений |
| senior | senior-2026 | Старший оператор: то же и правка тарифов и личных лимитов клиентов |

## Время банка

Банк работает по московскому времени. Суточный лимит считается по московским суткам, месячная квота — по календарному месяцу. Сценарий задачи может сдвинуть часы банка, например на 23:40, чтобы проверить ночные правила.

## События и очереди

| Что | Имя |
| --- | --- |
| Создание операции | Kafka, топик `bank.payments.created` |
| Смена статуса | Kafka, топик `bank.payments.status-changed` |
| Решение антифрода | Kafka, топик `bank.antifraud.decisions` |
| Уведомления | RabbitMQ, очередь `bank.notifications`, недоставленные — `bank.notifications.dlq` |

Ключ сообщений Kafka — номер клиента, в заголовках передаются `operationId` и `requestId`.

## Автоплатежи {release=1.1}

Ждать день платежа в тестовом контуре не нужно. Запрос `POST /api/v1/sandbox/autopayments/{id}/run` с токеном клиента исполняет автоплатёж сейчас, как будто наступил день платежа: по тем же правилам, с записью запуска, уведомлениями и событием. Пока предыдущий запуск ждёт проверки, новый не начинается.

О каждой завершённой попытке банк пишет событие в Kafka, топик `bank.autopayments.executed`, ключ — номер клиента. Топик появляется с первым таким событием.

Уведомления магазину банк отправляет из контейнера. Чтобы они дошли до программы на вашем компьютере, запустите её на любом свободном порту и укажите адрес `http://host.docker.internal:<порт>/<путь>`: адрес `localhost` для банка — он сам. Если уведомления не доходят, в журнале доставок будет ошибка: `ECONNREFUSED` — на этом порту ничего не слушает, `TIMEOUT` — программа не ответила за 5 секунд или её не пускает брандмауэр компьютера.

## Журнал запросов

Банк записывает каждый запрос к `/api/v1`: метод, путь, статус и `Idempotency-Key`. Номер запроса приходит в заголовке ответа `X-Request-Id`; его же можно передать самому в заголовке запроса.
