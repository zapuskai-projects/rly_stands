# Партнёрское API

Документ для магазинов, которые принимают оплату по QR-коду ЗапускБанка. Магазин выставляет QR-код на заказ, банк сообщает магазину об оплате и возврате на его адрес, магазин возвращает оплату покупателю целиком или частями. Как клиент платит по QR — в документе «Переводы. Функциональные требования», раздел «Оплата по QR».

Контракт: http://localhost:18400/api/partner-openapi.yaml, Swagger — http://localhost:18400/api/partner-docs/.

## 1. Магазин и вход

В тестовом контуре один магазин — «Лавка Гарипова». Его владелец — клиент банка ИП Гарипов Р. Ф., деньги за покупки приходят на его расчётный счёт.

Каждый запрос магазина несёт ключ в заголовке `X-Partner-Key`. Ключ магазина — в документе «Тестовый контур».

| Код | Когда |
| --- | --- |
| 401 `PARTNER_KEY_REQUIRED` | Заголовка нет |
| 401 `PARTNER_KEY_INVALID` | Ключ неверный |

## 2. QR-код

### 2.1. Выставить

`POST /partner/v1/qr`

| Поле | Что значит |
| --- | --- |
| `orderId` | Номер заказа в магазине: латиница, цифры, `.`, `_`, `:`, `-`, до 64 символов |
| `amount` | Сумма в копейках, от 1 копейки до 1 000 000 ₽ |
| `description` | Назначение платежа, от 1 до 140 символов; его видит покупатель |
| `ttlSeconds` | Срок действия в секундах, от 60 до 3600; по умолчанию 600 |

Ответ — QR-код. Содержимое кода для покупателя — поле `payload`, строка вида `zbqr://pay?id=<qrId>`.

Повтор с тем же `orderId` и той же суммой возвращает тот же QR-код ответом 200 и заголовком `Idempotent-Replayed: true`. Повтор с тем же `orderId` и другой суммой — отказ `ORDER_ID_REUSED`. На заказ выставляется один QR-код: если он просрочен или отменён, для новой оплаты нужен новый `orderId`.

### 2.2. Узнать состояние

`GET /partner/v1/qr/{qrId}` — состояние, сумма, сколько оплачено и возвращено, операция оплаты и время оплаты.

### 2.3. Отменить

`DELETE /partner/v1/qr/{qrId}` — отменяет неоплаченный QR-код. Повторная отмена отвечает так же, как первая. Оплаченный QR-код и QR-код, по которому идёт оплата, не отменяются.

### 2.4. Состояния

| Состояние | Что значит |
| --- | --- |
| `CREATED` | Выставлен, ждёт оплаты |
| `PAID` | Оплачен |
| `PARTIALLY_REFUNDED` | Часть оплаты возвращена |
| `REFUNDED` | Оплата возвращена целиком |
| `EXPIRED` | Истёк срок |
| `CANCELLED` | Отменён магазином |

`CREATED` → `PAID` → `PARTIALLY_REFUNDED` → `REFUNDED`; `CREATED` → `EXPIRED`; `CREATED` → `CANCELLED`. Срок считается по банковскому времени; в момент окончания срока QR-код уже просрочен.

## 3. Деньги магазина

- За оплату покупатель платит ровно сумму QR-кода.
- Магазин получает сумму за вычетом комиссии банка 0,7 %. Комиссия округляется до копейки по правилам арифметики: половина копейки и больше — вверх.

Пример: оплата 1 234,50 ₽, комиссия 8,64 ₽, магазину — 1 225,86 ₽.

## 4. Возврат

`POST /partner/v1/qr/{qrId}/refunds`, тело — `amount` в копейках.

- Возвращается вся оплата или её часть. Возвратов может быть несколько, пока их сумма не достигнет суммы оплаты.
- Деньги идут с расчётного счёта магазина на счёт, с которого платил покупатель. Покупатель получает СМС и пуш.
- Комиссия банка за оплату магазину не возвращается.
- Заголовок `Idempotency-Key` обязателен. Повтор с тем же ключом и той же суммой возвращает тот же возврат, с другой суммой — отказ `IDEMPOTENCY_KEY_REUSED`.

## 5. Уведомления магазину

### 5.1. Адрес

`PUT /partner/v1/webhook`, тело — `url` и `secret`. Адрес — `http` или `https`. Новые значения заменяют прежние; уведомления, созданные до сохранения адреса, не отправляются.

Банк работает в контейнере, и адрес `localhost` для него — он сам. Приёмник на своём компьютере указывайте через имя `host.docker.internal`, например `http://host.docker.internal:8080/webhook`.

### 5.2. Что приходит

`POST` на адрес магазина, тело JSON:

| Поле | Что значит |
| --- | --- |
| `event` | `qr.paid` — QR-код оплачен; `qr.refunded` — сделан возврат |
| `qrId` | QR-код |
| `orderId` | Номер заказа магазина |
| `amount` | Сумма QR-кода в копейках |
| `refundedAmount` | Сколько всего возвращено по QR-коду, в копейках |
| `operationId` | Операция оплаты для `qr.paid`, операция возврата для `qr.refunded` |
| `occurredAt` | Время события по банковскому времени |

Заголовки:
- `X-Event-Id` — идентификатор уведомления; одинаковый во всех попытках доставки одного уведомления, по нему магазин отличает повтор.
- `X-Signature` — подпись: `sha256=` и HMAC-SHA256 тела запроса ключом `secret`, в шестнадцатеричном виде. Подпись считается по телу ровно в том виде, в каком оно пришло.

Магазин проверяет подпись и отвечает кодом 2xx. Уведомление с неверной подписью магазин не принимает.

### 5.3. Повторы

- Уведомление доставлено, если приёмник ответил кодом 2xx за 5 секунд.
- Иначе — ответ не 2xx, нет ответа за 5 секунд, приёмник недоступен — банк повторяет отправку через 10, 30 и 60 секунд. Всего четыре попытки. Паузы между попытками считаются по настоящему времени, а не по банковскому.
- После четвёртой неудачной попытки уведомление больше не отправляется.

### 5.4. Журнал доставок

`GET /partner/v1/webhook/deliveries` — уведомления от новых к старым, фильтры `qrId` и `event`.

| Статус доставки | Что значит |
| --- | --- |
| `PENDING` | Идут попытки |
| `DELIVERED` | Приёмник ответил кодом 2xx |
| `FAILED` | Все четыре попытки неудачны |

У каждой попытки — номер, время по банковскому времени, код ответа приёмника или ошибка (`TIMEOUT`, `ECONNREFUSED`, `ENOTFOUND` и другие) и длительность.

## 6. Отказы

| Код | Когда |
| --- | --- |
| 400 `VALIDATION_ERROR` | Неверный формат запроса |
| 404 `QR_NOT_FOUND` | QR-кода нет или он выставлен другим магазином |
| 409 `ORDER_ID_REUSED` | Заказ уже выставлен с другой суммой |
| 409 `QR_ALREADY_PAID` | Отмена оплаченного QR-кода или QR-кода, по которому идёт оплата |
| 409 `QR_EXPIRED` | Отмена просроченного QR-кода |
| 409 `QR_NOT_PAID` | Возврат по неоплаченному QR-коду |
| 422 `REFUND_EXCEEDS_PAYMENT` | Сумма возвратов больше оплаты |
| 422 `INSUFFICIENT_FUNDS` | На расчётном счёте магазина не хватает денег для возврата |
| 422 `IDEMPOTENCY_KEY_REUSED` | Ключ повтора уже использован с другой суммой |
| 422 `WEBHOOK_URL_LOOPBACK` | Адрес уведомлений указывает на сам банк (`localhost`, `127.0.0.1`) |
