# Локальная панель стендов

Контроллер слушает в контейнере порт 18490. На хосте доступен только `http://127.0.0.1:18490`. Порт и данные привязаны к одному набору. Повторный запуск из той же папки переиспользует контроллер. Локальная платформа предоставляет назначения, права и результаты через существующий stand-token API.

| Запрос | Назначение |
|---|---|
| `GET /api/meta` | Версия набора, идентификатор экземпляра, версия протокола и сборки интерфейса |
| `POST /api/session/bootstrap` | Однократно обменять nonce из фрагмента ссылки на cookie сессии и CSRF-токен |
| `GET /api/session`, `POST /api/session/logout` | Проверить или закрыть текущую браузерную сессию |
| `GET /api/state` | Назначения, состояние Docker и платформы, активная попытка, результаты, выполняющиеся операции |
| `POST /api/plans` | Получить двухминутный план по полям action, target или version и clientRequestId |
| `POST /api/operations` | Передать planId и, если нужно, confirmation с checked и token из плана. При принятии возвращает HTTP 202 и operationId |
| `GET /api/operations`, `GET /api/operations/:id` | История с offset/limit, необязательный фильтр requestId, наблюдаемые этапы операции |
| `POST /api/operations/:id/cancel` | Отменить операцию, пока она в очереди |
| `GET /api/modules/:key/logs` | Последние записи контейнеров выбранного модуля |
| `GET /api/work`, `GET /api/work/file?path=…` | Страница списка и содержимое существующего файла UTF-8 до 1 МиБ |
| `PUT /api/work/file` | Передать path и text с исходным ETag в If-Match. Ответ 412 означает, что файл изменился |
| `POST /api/device-login`, `GET /api/device-login/:id` | Получить код устройства и проверить подтверждение входа на платформе |

Для изменений браузер отправляет JSON, свой локальный Origin, X-CSRF-Token и X-UI-Build-Id. При PLAN_STALE требуется новый просмотр условий. После обрыва браузер перечитывает журнал по идентификатору запроса. Прерванное действие остаётся в истории до решения пользователя.

При обновлении образ и ресурсы панели меняются вместе. На хосте запущенный `./stand panel` обслуживает запрос на обновление. Старый контроллер сохраняется на время проверки нового. Обычный перезапуск контроллера сохраняет учебные контейнеры. При ошибке история показывает, до какого этапа дошло обновление.

## Проверка перед выпуском

До публикации версии можно проверить рабочую копию из корня набора:

```sh
docker build -t stands-kit-pult:local ./pult
STAND_PULT_IMAGE=stands-kit-pult:local ./stand panel
```

Для проверки изменений на своём компьютере используйте отдельное тестовое окружение с учебными данными. В CI обновление проверяется на двух разных версиях образа.

В каталоге `pult` выполните `npm ci`, `npm run typecheck`, `npm run lint` и `npm test`. Для браузерного набора на Linux установите Chromium через `npx playwright install chromium` и запустите `npm run test:panel`. Полный сценарий с учебным банком, очередью и обновлением открытой вкладки запускает CI в отдельном одноразовом Docker-окружении. Снимки и журнал доступны в артефакте `panel-proof`.

Backend платформы должен обслуживать `GET /api/stand-kit/tasks/:labId/state` до выпуска образа панели. Публикация образов выполняется существующим процессом релиза набора.
